# v18.2 - stale JavaScript shadowing TypeScript source

## Diagnosis from the Windows logs

The source code reports 8 lazy route entries and `vite.config.ts` has `build.manifest: true`, yet Vite repeatedly emits the *same* 583.09 kB `index-BsXC8eqn.js` as before the lazy changes and produces no manifest. That combination strongly indicates stale `.js` companions generated by the earlier `tsc -b` command.

Vite may resolve `src/app/App.js` in preference to `App.tsx` for extensionless imports. It may also discover `vite.config.js` in preference to `vite.config.ts`. Therefore a text-only check of TypeScript source was not sufficient. The absence of `dist/.vite/manifest.json` is a downstream symptom.

The v18.2 patch adds a **filesystem-aware guard** that finds source-side `.js` companions in `src/` and conflicting root Vite/test config files. It also forces the intended Vite config with `--config vite.config.ts`. The cleanup command **moves only matching files to a timestamped backup**, never deletes your original TS/TSX files or unrelated handwritten JavaScript. The backup folder is git-ignored.

## Install (Windows PowerShell)

1. Commit your current code or back it up.
2. Extract the overlay ZIP to `D:\`, not `D:\procurepilot-ai\`, and allow replacement of the files named in the archive. Don't overwrite `.env` or delete `package-lock.json`.
3. Run from `D:\procurepilot-ai\frontend`:

```powershell
npm run check:shadowed
npm run clean:shadowed
npm run test:tooling
npm run check:overlay
npm run typecheck
npm run test
npm run build
npm run test:e2e
npm audit
```

`check:shadowed` is expected to fail with a clear list **if** old `.js` companions are present. `clean:shadowed` then quarantines them, keeping a backup under `.generated-js-quarantine/<timestamp>/`. Review the printed list when it runs. If no JS companions exist, it does nothing; in that case provide the output of `npm run check:shadowed` plus `Get-ChildItem . -Filter "vite.config*"` for further diagnosis.

Do **not** manually delete all `.js` files, all dependencies, or the original Laravel files. Do not run `tsc -b` with emit enabled again; this project uses `npm run typecheck` (`tsc --noEmit`).
